## 09｜Map System

不一次載入整個世界。

規劃採用：

- Chunk Streaming（分區串流）
- LOD（依距離調整細節）
- Dynamic Loading（動態載入）
- Asset Streaming（資產串流）

重要地區使用高細節模型。

**世界範圍：**以台灣／台中市中心、海線、山線、屯區及既定生活場景為設計原型，正式地圖採虛構地名與配置。完整探索範圍依 `MAP-TAICHUNG-SYSTEM.md`，分區載入不代表刪除其他地區。

**區域管理：**每個區域需規劃場景資產、碰撞、NPC、任務、互動及持久狀態。載入與卸載不能造成任務遺失、資產重複或狀態重置。

需測試步行、駕駛及快速移動時的區域交界、預載、遠景與載入失敗處理，避免道路消失、車輛掉出地面及建築突然出現。

## 13｜核心原則

先完成小而能玩的 Prototype，再逐步擴充：

角色 → 場景 → 車輛 → 任務 → 帳號 → 存檔 → 多人 → 完整幻都世界

此順序保留原有發展方向，實際工作需依系統依賴調整。原型中的登入畫面、基本存檔與正式帳號同步應清楚區分，不因列在不同階段而刪除既定原型需求。

**最終範圍：**小型原型是操作及架構驗證，不能取代完整開放世界。角色自訂、寵物、住宅、生活、犯罪任務、年代車輛及多人合作均依相關企劃保留。

## 14｜角色控制、動畫與物理碰撞

需評估角色控制器、動畫狀態、碰撞及載具物理方案。具體引擎或套件待選型及實測，不由 Three.js 或模型可顯示推定已完成。

需求包含：

- 第三人稱移動、轉向、跑步與相機跟隨。
- 地面、坡度、台階、建築與互動物件碰撞。
- 相機遮蔽處理，避免長時間卡入牆面。
- 行走、跑步、坐下及互動動畫過渡。
- 上下車、角色座位與載具控制切換。
- 車輪接地、轉向、加減速及既定損壞狀態。
- 不同身高、身形與服裝的互動貼合。

操作、比例及品質依角色、載具與視覺文件驗收。新增技術方案不能未經確認取消既定控制或外觀需求。

## 17｜Audio 與多人語音

依 `AUDIO-VOICE-SYSTEM.md` 保留配音、多語字幕、年代聲景、動態音樂、3D 空間音效及多人語音需求。

可評估瀏覽器音訊能力及相容工具，具體方案需支援：

- 音源位置、距離及方向變化。
- 遮蔽與室內外聽感。
- 人物語音、環境音與音樂的音量控制。
- 字幕與對話同步。
- 年代切換及場景載入時的音源管理。
- 音訊載入、播放限制及串流失敗處理。
- 隊伍與距離語音的傳輸、權限及玩家控制。

位置連線、音效播放與玩家語音傳輸是不同功能，需各自選型及測試。第一版原型可依聲音文件暫不實作多人語音，仍須保留後續需求。
